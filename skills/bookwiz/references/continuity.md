# Canon and continuity

`bookwiz.json` keeps accepted characters, worlds, facts and timeline entries in `canon`. Markdown files under `canon/` support richer character sheets, relationships and research. Keep important accepted facts consistent between the summary metadata and the longer notes.

Before drafting, identify the chapter's viewpoint, place, time, physical constraints and what each participant knows. Read its summary and the previous chapter's consequence. Use the bounded context packet as a starting point, then read a specific source file when precision requires it.

Classify a suspected conflict before acting:

| Finding | Response |
| :--- | :--- |
| Direct contradiction of an accepted fact | Quote both places and propose the smallest repair |
| Different character beliefs | Preserve the difference unless narration presents both as objective fact |
| Timeline or travel impossibility | Show the conflicting times/distances and identify affected chapters |
| Deliberate mystery or unreliable narration | Preserve it and add a tracking note |
| Missing information | Mark it open; do not create a fact to close the gap silently |
| A changed brief or world rule | Record the accepted change and flag dependent drafts |

A continuity report names the fact, source, affected chapter and proposed next step. Avoid vague labels such as “inconsistent worldbuilding” without a passage. Do not rewrite every chapter because one date changed.

When revising canon, take a snapshot first, update the accepted ledger, and inspect only dependent chapters. For multi-world fiction, tag facts by world/era and distinguish global rules from local exceptions. For nonfiction, treat dates, names, units, quotations and source interpretations as continuity facts too.
